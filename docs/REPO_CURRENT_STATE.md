# Current state

Updated 2026-11-03. This is the only current capability and qualification record.

## Implemented scope

The development version supports project-based lattice QCD research collaboration over the existing trusted control plane. CLI, Python and the local workbench use one submit/advance path. Protocol/state/execution schema remains `0.4`; scientific artifact schema remains `0.1`.

- Each installation begins with empty `library/wiki`, `library/skills` and `library/methods`. No external private wiki is imported. Versioned candidate/reviewed/contested assets include applicability, source references and operator review receipts.
- Projects have immutable revisions. Runs bind a Project snapshot, input identity and explicitly selected reviewed method versions. Project evidence captures retain registered producer-scoped artifacts and sidecars; they provide readable history without execution/recovery authority.
- Live planning uses PI → Postdoc and review uses independent Reviewer → PI, through the Python OpenAI Agents SDK. The same canonical scientific adapter retains Host numerical checks. All SDK model/tool effects pass the existing budget/fence boundaries; retries, nested agents, SDK sessions and handoffs are disabled.
- Role tools support local library search/reads, candidate creation, full named context reads, project evidence, public INSPIRE metadata and paginated arXiv HTML text. Literature unavailability is explicit; this is not general browsing or figure inspection.
- Questions, responses and references persist through bounded scientific revisions. Project history is projected into unresolved issues, conflicting answers and conditional accepted claims, with original resolutions and evidence available on demand. Verified historical issue identities can be revisited without reloading all resolved discussions. Concrete PI checks reach coding requirements. Information-dependent plans stop before analysis. Safe revisions use existing replan cycles; numerical warnings, original failure handling, budget stops and final human acceptance remain distinct.
- The independent Codex SDK remains the sole coding backend. Reviewed sources are frozen into read-only coding inputs; final analysis remains a verified self-contained program. Generated code is not automatically promoted to reusable methods.
- C2 and Normalization retain their Host checks. The new `replica_observables` contract binds definitions, units, kinematics and sample identities, checks bootstrap/jackknife arithmetic and always retains limitations concerning physical suitability and original resampling provenance.
- The project workbench provides version-checked edits, investigations, discussions, questions, library inspection, evidence and human decisions. A deterministic final report includes independent review, PI/Postdoc conclusions, Host warnings, remaining questions, human conditions and exact artifact references.
- Existing leases, fencing, idempotency, cancellation, WAL/FULL durability, immutable acceptance, sealed execution and fixed native macOS `/private/tmp` qualification remain in force.
- Research calls use one Agents SDK transport and coding uses one Codex backend. Current artifact fields share one definition; old client parameters, configuration aliases, duplicate schemas/metadata and execution-version compatibility paths have been removed. Unsupported execution layouts are rejected explicitly, and Code projections receive full hash checks.

- Token deployment policy has one entry in `settings.py`: 256,000 input tokens, 32,768 research output tokens including reasoning, and a shared 0.76 compaction ratio. Both paths read the same derived 194,560-token threshold; the old research policy module and separate application output field have been removed. Native Code output remains SDK-managed.
- Complete explicit research and Code model inputs are counted before dispatch, with a 256,000-token hard ceiling. Research compacts working history above 194,560 tokens while retaining initial scientific state verbatim; Code uses native compaction at 194,560 within its 243,200 effective window and a separate actual HTTP admission check. Counting failures and excess stop dispatch without silent truncation. Research compaction consumes the existing model-call allowance and leaves room for a conclusion.
- Reviewer initial views retain every Host finding/warning and point to the full method through a digest-bound named read. Pre-resource failures bind the real started attempt, without fabricating a model reservation. Unregistered project evidence references return a correctable lookup result; registered-data corruption remains a hard failure.

## Practical limits

Research roles share four model calls per canonical attempt, including compaction, with one call reserved for the second role. Generation now allows 32,768 output tokens including reasoning, and roles are asked to keep their structured conclusions concise. Initial protected state may exceed the compaction threshold up to the hard input ceiling; mandatory scientific facts are not discarded to make it fit. A burst of tool output beyond the hard ceiling stops even compaction. Per-request input limits are not a cumulative Run token or spending budget and do not measure provider-internal hosted-tool context.

The configured request timeout (180 seconds in the live qualification) applies to each research generation, count, compact and tool effect. The attempt requests the existing 900-second policy window, clipped by remaining budget and its original Host deadline, with 30 seconds reserved for cleanup and settlement; it is not automatically renewed. Cancellation is cooperative and cleanup can overrun that allowance, in which case original fencing still rejects expired settlement. Repeated evidence reads revalidate growing control journals and remain a performance limitation. Every intermediate journal prefix retains its integrity and numeric checks. Model-call limits, WAL/FULL durability and acceptance authority remain unchanged.

Generated research Code requests the existing 900-second producer window. Native coding is limited to 400 seconds within the roughly 450-second backend reservation, leaving room for verification and sealing; remaining policy budget and original deadlines still constrain every stage. The worker lease is requested for 960 seconds but cannot extend the original producer deadline. Completed Code must be delivered within its original backend reservation. New data, physical definitions or incompatible outputs require a new configured Run. Live C2, Normalization and paid long-context compaction have not been rerun after token-policy consolidation and the output-limit increase. Arbitrary QCD methods, independent physics validation, large-corpus RAG, HPC and distributed execution are not qualified. Retired Run layouts have no in-place migration; retain their original supported runtime for original Hosts.

Method registration verifies source/validation bindings and operator decisions, not that arbitrary submitted checks were executed or sufficient. Project captures omit raw datasets, control databases, credentials and unregistered failure traces; retain the original Host or appropriate backups. Cancellation remains available when the data workspace is unavailable and reports that its Project capture could not be updated. Paper text reads do not inspect figures. Software checks and synthetic calibration do not establish physics readiness.
