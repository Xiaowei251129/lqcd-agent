# Current state

Updated 2026-11-04. This is the only current capability and qualification record.

## Implemented scope

The development version supports autonomous project-based lattice QCD research collaboration over the existing trusted control plane. CLI, Python and the local workbench share one submit/advance path and one native Host driver. Coordinator schema is now `3`; protocol/state/execution schema remains `0.4`, and scientific artifact schema remains `0.1`. Old Hosts require their original supported runtime; there is no in-place migration or rewriting of accepted results.

- Planning uses PI → Postdoc, coding uses the sole native Codex SDK backend, Analysis executes actual numerical code, and review uses independent Reviewer → PI synthesis. The Host owns admission, execution authority, leases, fencing, cancellation, budgets and publication. Role separation does not establish independent model-family agreement or physical correctness.
- Ordinary scientific disagreement, warnings and missing information no longer require a human response. Bounded revisions continue automatically; terminal reports record `scientific_outcome=supported|qualified|inconclusive` and `decision_origin=system`. Unresolved caveats remain in the report. Permission responses are recorded separately as `authorization_decision`; they are never scientific endorsements.
- Only an explicit extra-authority request opens the human gate. Approval cannot override security, data-integrity or policy failures. Known ended resource failures can produce an evidence-bound inconclusive report. Hard native interruption retains its actual committed control closure and a truthful execution-failure explanation, without inventing successful Code/tool evidence or a scientific final report.
- PI can propose a typed additional experiment. Supported analysis-parameter changes and independently reviewed method choices create linked immutable Runs through the original start path, retaining the same dataset, interpreter, permissions and shared research-task account. Run admission and quota membership commit atomically. Exact crash recovery reuses the admitted input/method bytes; unsupported, repeated or exhausted proposals retain an unexecuted reason.
- The installed task limits are four Runs, 128 actual model requests, 8,000,000 explicit input-plus-output reservation units and a 3,600-second dispatch deadline. Research generation, native Code generation and compaction, including native retries, share this account. Missing usage retains the maximum reservation. These units are not a USD billing ceiling and do not measure every provider-internal context or hosted-tool fee.
- Each installation begins with empty `library/wiki`, `library/skills` and `library/methods`. Attributable candidates can be reviewed by an independent Reviewer from a different attempt. Method promotion additionally requires actual Host-executed finite calibration of the exact sealed, successfully analyzed program. The manual CLI uses the same calibration path; uploaded `passed:true` receipts cannot grant reviewed status. C2 and Normalization have supported validators; generic methods remain candidates.
- Projects have immutable revisions, evidence captures and optional immutable operator comments/questions/evidence. Contributions enter the next safe research attempt, including the linked experiment ancestry, through full digest-bound context reads. Text cannot grant authority, change sealed results or restart a closed Run. Captures remain readable history, not execution/recovery authority or raw-data backups.
- Questions, responses and references persist through bounded revisions. Project history retains source-attributed conclusions and conflicting issues. Concrete PI checks reach coding requirements. Role tools provide local assets, registered Host/Project evidence, public INSPIRE metadata and paginated arXiv HTML text; literature unavailability and uninspected figures are explicit.
- C2, Normalization and `replica_observables` retain deterministic Host checks. The replica contract binds definitions, units, kinematics and sample identities; arithmetic checks do not establish physical suitability, configuration independence or original resampling provenance.
- All deployment token limits have one entry in `settings.py`: 256,000 explicit input tokens, 32,768 research output tokens including reasoning, 128,000 native Code output tokens, and a shared 0.76 compaction ratio giving 194,560 tokens. Code uses the native 243,200-token effective window; its gateway separately recounts and admits every actual request. Research compaction retains protected scientific state verbatim. Counting failure or excess stops dispatch without silent truncation.
- Research uses the Python OpenAI Agents SDK without nested agents, handoffs, persistent SDK sessions or SDK-owned approvals. The balanced policy allows eight model calls and 32 tool calls per research attempt. Sequential roles share the existing tool/time headroom and reserve actual input counting and final generation. Exploratory batch calls refused for this reservation are recorded as unexecuted, without tool effects or evidence; final turns disable tools. Actual Host refusal, lease expiry, request failure and cancellation still fail normally. No budget limit is raised.
- Postdoc and Reviewer output schemas use the pinned SDK strict-schema transformation for both counting and generation. Nullable fields remain required on the wire. Read-only inspection can verify a published ordinary-resource prefix during an active invocation; unknown effects, unowned changes and unsafe gaps still refuse inspection and cannot become runnable.
- Code workflows preallocate the existing Code Host controller lease for verification and publication. The consumer retains its original invocation deadline and active-time budget; generation, producer and task-dispatch limits are unchanged. Ordinary budget journals check each frozen intent and canonical prefix/index chain, then perform one complete replay that still validates every intermediate lifecycle and budget state. A one-entry cache reuses only strict decoding of the complete freshly read SQL value, with independent copies; revision, authorization, state and live fencing remain fresh.
- Generated numerical analysis and calibration have networking disabled. Coding commands use the pinned native managed public-network proxy, private/local-target guard, no Unix-socket allowlist, ephemeral HTTP port and no SOCKS listener. Native approval is `deny_all`/`never`; a model cannot self-authorize sandbox escalation. Model HTTP transport uses the private Host gateway outside the command sandbox.
- WAL/FULL durability, exact idempotency, boot/PID checks, original source fencing, immutable accepted results, code sealing and numerical provenance remain. Native failures/cancellation/deadline expiry use the actual worker state and original revoke/kill/drain closure, without fabricated normal completion. A committed failed Attempt with no registered result now completes the original control closure before its exception is propagated, and the original Project capture path retains that failure. Started, uncertain or corrupted state cannot enter this automatic closure.

## Practical limits

Autonomy means work can conclude within its existing authorization; it does not promise a positive physics result. Unsupported experimental scope, missing data, incomplete evidence, exhausted budgets and failed execution remain visible. System review cannot certify arbitrary QCD methods. Wiki/skill review is attributable scientific judgment; finite method calibration is limited to the declared supported families. Source, inputs, results, environment and validator identities are retained.

The configured request timeout applies to individual research generation, counting, compaction and tools. The attempt requests the original 900-second window clipped by remaining policy/task authority, with 30 seconds reserved for settlement. Cancellation drains owned effects and can overrun that allowance; expired fencing still rejects publication. Redundant full-prefix replay and repeated exact-byte strict decoding have been removed. Journals still retain full prefixes and large serialized values; the one-entry decoder cache does not bound their byte size, memory or disk cost.

Generated Code requests the existing 900-second producer window. Native coding is limited to 400 seconds within the roughly 450-second backend reservation, leaving verification/sealing time. The 960-second requested worker lease cannot extend that original producer deadline. Shared task expiration stops dispatch and triggers owned native cleanup. Unknown model usage is conservative and is not a complete provider billing statement.

New data, physical definitions or incompatible outputs require a new configured investigation. General figure-reading, large-corpus RAG, arbitrary-QCD certification, HPC and distributed execution are not qualified. Execution qualification remains native macOS with owned local storage under `/private/tmp`; Linux source/build checks alone do not qualify runtime behavior.
