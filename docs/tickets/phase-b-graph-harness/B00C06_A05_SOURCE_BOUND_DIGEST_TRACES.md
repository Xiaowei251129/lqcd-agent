# 补齐 A05 内容摘要的来源绑定语义轨迹

## Goal

在不改变A05 runtime内容摘要与A06 reservation语义的前提下，使同一Code场景在不同fresh Run/workspace根下产生唯一、可验证的exact semantic trace。增加显式trace `0.5`，保持旧`0.1–0.4`语义不变，解除B03的来源摘要投影阻塞。

本票为待审批方案，未实施。B00C05已completed并解决首次reservation分类；本票不重开或替代C05。

## Why

A05要求task冻结validated execution/artifact heads，manifest再绑定task；A06 aggregate reservation必须绑定exact task/manifest digests。真实Run head包含临时canonical output root，因此同一任务在两个fresh根下的raw task/manifest digests必然不同。A07同时要求临时根不影响exact semantic trajectory，且不能忽略或伪造canonical digests。

现有trace0.4仅把已知execution/artifact/checkpoint等head及external Pause的reservation引用作为结构引用，`resource_reserved.payload.task_digest`、`workspace_manifest_digest`及相应派生摘要仍是literal。只给event添加结果摘要或把task放进proof，不能解决execution source中已有的literal；额外未被引用的source还会被正确拒绝为orphan。

`tests/phase_b/test_b03_task_trace_boundary.py`提供可复现反例：真实B02 start、plan注册、Code target advance及C05 initial producer，固定UUID和时钟、相同独立immutable Git base，两次fresh目录。基础trace exact相同；contract-shaped task仅execution/artifact/budget-event引用和自身摘要不同，manifest仅task引用和自身摘要不同；production builder/replayer接受对应reservation，但trace0.4投影不同。另有raw tamper拒绝和同根材料变化仍可区分的对照。

这些是冻结合同的数据依赖反例。Task/manifest为contract-shaped fixture，reservation仅经production builder/replayer验证而未推进producer phase；它们不冒充完整B03 closed validators、Backend执行或645项canonical runtime证据。数学依赖来自A05/A06必需字段，不依赖fixture的可选字段命名。

## Scope and Version Handoff

- 新增trace0.5及必要的显式proof版本/typed source编码；旧版本不重新解释、不自动升级。
- 在本票内先完整审计A05/A06摘要DAG，并以project-owned derivation表冻结每条已知引用的source kind、字段路径、摘要算法、身份绑定和依赖顺序。覆盖task → manifest → aggregate reservation → immutable external core → Pause，以及receipt/seal/external result/verification/canonical result/Code Bundle/Analysis spec后继链，不只修复一个`task_digest`字段。
- 只有通过raw canonical bytes、内容摘要、exact identity和完整依赖闭包校验的引用才转为semantic digest。区分整个JSON内容摘要、排除自描述字段的摘要、artifact member原始bytes摘要，不能把不同算法视为同一对象摘要。
- 摘要来源validator只证明trace provenance，不能授予runtime authority或代替B03的closed-schema、ingress、containment、verification和registry校验。后续B03必须使用同一真实对象完成canonical证据；本票fixture不能计入B03 requirement。
- 对Host-owned workspace物理根、运行时clock、opaque provider identity，明确A07允许的projection及绑定证明。来源不足、跨operation混用、伪装成临时目录的material path必须拒绝，不能用全局字符串替换。
- 完成后仅以trace0.5替代B03 frozen entry中trace0.4的A05新轨迹适用版本；B00–B02现存轨迹继续原版本，case0.3及C05 handoff保持。B03正文保持`b78c15a`冻结内容。

## Requirements

1. Derivation表必须标明哪些摘要含execution身份/临时根，哪些是应保持可区分的材料摘要；不存在把所有64位hex统一替换的通用规则。调用方不能自行指定可排除的字段或trusted aliases。
2. Raw proof先验证，再投影；错误checksum、missing/duplicate/orphan/cyclic source、mixed-version、wrong kind/algorithm、foreign Run/Attempt/producer/workspace/Pause、stale session和被替换path均失败。不能仅凭字段名相同认定引用合法。
3. 自描述checksum须验证其exact算法后才能映射到同一对象semantic identity，不能产生自引用环或不校验就删除。A03 member SHA-256与对象自描述摘要不同，必须各自闭合。
4. Task requirements、policy、base、artifact内容、verification command/result、seal evidence、usage、operation/lease/phase、status、route或outcome变化必须改变语义轨迹或被拒绝。只有A07明确允许的临时值可以在证明绑定后投影。
5. Same-case两次fresh根trace exact相同；task/manifest/raw reservation checksum仍各自真实且因根不同而可不同。除了prestart链，还需有覆盖上述完整DAG的contract-level正负fixture，防止后续bundle/Analysis遇到同类缺口。
6. Collector、matrix scenario验证与exit semantic摘要使用同一个投影实现；新版本不能只在unit helper中有效。旧版本仍独立通过，旧golden不得整体升级以隐藏差异。
7. B00C06通过后，B03仍须独立完成28项construction、645项runtime以及trusted verification资源事务接线。不能把本票通过等同于B03必然完成。
