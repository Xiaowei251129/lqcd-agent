# Data and security

Host code owns paths, identities, permissions, leases, transitions, resource settlement and publication. Domain outputs and backend declarations cannot grant authority. External actions need scoped authorization.

Preserve fencing, idempotency, symlink/hardlink checks, private-root ownership, SQLite WAL/FULL, foreign keys, accepted-result immutability, source digests and stop-owner checks. Replay and fork accept current validated sources only.

The application key lives in the operator workspace's ignored `.env`, owned by the operator with mode 0600. Never commit credentials. Application settings read the file without exporting secrets into child environments. An explicit `--live` opts in to paid API calls; ordinary tests remain offline; the workbench requires explicit live activation.

Codex uses its SDK-bundled runtime, a fresh private `CODEX_HOME`, API-key login and ephemeral credential storage. It does not use the interactive operator's Codex login or configuration. Tools and live web search are available. Command networking follows the immutable task's explicit boolean network policy; the current live task profiles enable it. SDK automatic review handles permission requests. The Host supplies task instructions, constrains the initial filesystem profile and validates the final file proposal against the task's persistent write paths. SDK tool starts/completions are observed, counted and bound into delivery evidence; they are not rejected merely for using tools. Application credentials remain outside the model context and worker child environment.

The current CLI coding example only modifies `sample.py`. Host fencing, path checks, immutable base comparisons and independent syntax verification precede consumption. Its Analysis command requires an AST equivalent to `def value(): return 2` before execution and asserts the integer result. This narrow example is not an execution sandbox for arbitrary generated programs. General program execution requires separately qualified OS isolation.

Canonical generated scientific Analysis uses the qualified execution boundary after fresh Code/Plan preparation. Its frozen specification binds consumed JSON identity, disjoint parameters, exact program bytes, interpreter/library identity, enabled network policy and timeout. The existing resource port owns admission and settlement, and invocation leases cover calculation plus role processing. Analysis publishes through its normal Run-result/manifest writer. The initial Reviewer request contains Host-derived aggregate diagnostics. Explicit named evidence tools may supply stored analysis outputs, including replica-level results, to the configured model; raw input files and withheld answers have no general file-reading tool. A pending Plan cannot dispatch Code, and scientific confirmation remains a human decision.

The research-case assessment tool uses the pinned Codex runtime's explicit local sandbox profile. Its candidate workspace contains the verified program and one input payload, with interpreter libraries readable. References, original research paths and application credentials are excluded. Network access is enabled as requested; review the exact program before supplying measured inputs. This grading process has CPU/wall/output bounds and performs no model/API call. Synthetic probes cover permitted workspace access, denied outside reads/writes and allowed loopback networking before measured inputs are evaluated. Failed calibration prevents measured-input execution. Assessment reports have no authority to advance a Run or accept a scientific result.

The local workbench uses loopback, exact browser origin and a session token. Project metadata and evidence APIs do not accept arbitrary shell commands or control roots. A missing Host permits new work in a new Host; old project copies remain read-only.

Scientific reports must distinguish synthetic and measured inputs, record methods and provenance, and require appropriate scientific review. A passing software or numerical benchmark is not physics acceptance. Do not silently replace raw data, accepted results or failed observations to obtain a pass.

Installed build metadata and owned workspace resolution do not broaden code-execution permissions. The private Host remains the filesystem access boundary; existing SQLite file modes are retained. Read-only inspection shares the coordinator's exact schema and private-Host checks without opening its writer or running durability probes on the existing authority. Doctor uses a fresh private root for those probes.

Portable archives remain private inside the Host and include only closed Run evidence and its explicitly hash-bound domain members. No coordinator/checkpoint SQLite file, backend authentication home, external raw data or backend worktree is copied. The static format grants no Run execution or recovery authority. Verification never extracts members and rejects duplicate names, traversal, symlinks, unsupported file/compression types, oversized content and digest mismatches. Preserve a trusted archive digest separately; a self-consistent bundle alone does not authenticate its origin. Operator cleanup and transport to durable storage remain explicit.

Scientific input identity is frozen before execution. Dataset fingerprints and headers may appear in role context; raw CSV contents are neither placed in model messages nor copied into evidence archives. Complete supplied role context is retained locally; the Reviewer projects command logs out of its model view. References permit digest-checked named sections and project/library evidence. Explicit research tools separately admit bounded public literature reads; arbitrary filesystem paths remain unavailable. Model schemas exclude Host identity and execution paths; validated proposals are materialized by the Host. Existing scientific approval, resource accounting and stop ownership remain unchanged.

## Research SDK and local assets

Provider, malformed-model and refusal errors retain safe type/status diagnostics without copying private response bodies into derived error records. Attributable model outputs remain in the private research evidence stream; sanitizing an error does not erase that evidence.

PI/Postdoc/Reviewer tools are named Host functions, not generic filesystem or shell access. Model/tool effects are separately admitted; SDK retries, sessions, handoffs and nested agents are disabled. Literature requests use fixed INSPIRE/arXiv hosts without redirects and bounded responses. Search terms and requested paper IDs are sent to those services; private raw data and credentials must not be included in queries. Papers and stored notes remain untrusted evidence, never tool or approval instructions. HTML text reads do not establish figure inspection.

Local assets may enter model context through explicitly named reads. Candidates retain provisional status; only explicit operator commands review assets or register methods. Validation receipts bind exact source bytes but do not prove that arbitrary operator-supplied checks were scientifically sufficient. Reviewed code is snapshotted atomically and supplied read-only to the existing Code backend. It receives no direct execution permission.

Project captures verify registered producer scopes and copy only bound evidence. Raw-data backups, live SQLite, backend credentials and recovery authority are excluded. Historical accepted labels require the actual accepted terminal artifact and human decision. CAS metadata edits cannot alter a Run's frozen project version. Model discussions cannot grant acceptance or erase Host numerical warnings.
