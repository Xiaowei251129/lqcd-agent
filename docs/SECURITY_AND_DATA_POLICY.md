# Data and security

Host code owns paths, identities, permissions, leases, transitions, resource settlement and publication. Domain outputs and backend declarations cannot grant authority. External actions need scoped authorization.

Preserve fencing, idempotency, symlink/hardlink checks, private-root ownership, SQLite WAL/FULL, foreign keys, accepted-result immutability, source digests and stop-owner checks. Replay and fork accept current validated sources only.

The application key lives in the operator workspace's ignored `.env`, owned by the operator with mode 0600. Never commit credentials. Application settings read the file without exporting secrets into child environments. An explicit `--live` opts in to paid API calls; ordinary tests remain offline; the workbench requires explicit live activation.

Codex uses its SDK-bundled runtime, a fresh private `CODEX_HOME` and ephemeral API-key login to the worker's loopback gateway. The real application key stays in the Python worker; native Codex receives only a random token valid for that gateway's lifetime. It does not use the interactive operator's Codex login or configuration. Tools and live web search are available. Command networking follows the immutable task's explicit boolean network policy. Enabled coding commands use the pinned native managed proxy with public-domain access and its local/private-target guard; no local host/IP or Unix-socket allow entry is installed. Each job uses an ephemeral HTTP proxy listener with SOCKS disabled. SDK `ApprovalMode.deny_all` maps to native `never`: ordinary in-profile tools run automatically, while permission-escalation requests are rejected before the effect. Neither model text nor a second model reviewer can reopen the frozen boundary. The Host supplies task instructions, constrains the initial filesystem profile and validates the final file proposal against the task's persistent write paths. SDK tool starts/completions are observed, counted and bound into delivery evidence; they are not rejected merely for using tools. Application credentials remain outside the model context and worker child environment. The gateway counts the complete explicit request with the same provider before forwarding it, rejects implicit remote history and uncounted request fields, and stops further upstream admission after exhausted/invalid counting, input-limit or permanent generation failure. Only read-only counting retries connection errors, with at most three traced attempts sharing the original deadline and identical input; the gateway does not itself retry generation. Transient generation faults remain owned by native Codex recovery within its original operation budget, with fresh input counting and conservative unknown-usage records. Gateway records contain request hashes, counts and bounded failure-stage/status/type diagnostics, not request/provider-error bodies or credentials; shutdown closes owned connections. Input counting sends the same selected context to the configured provider and is not an offline tokenizer.

The current CLI coding example only modifies `sample.py`. Host fencing, path checks, immutable base comparisons and independent syntax verification precede consumption. Its Analysis command requires an AST equivalent to `def value(): return 2` before execution and asserts the integer result. This narrow example is not an execution sandbox for arbitrary generated programs. General program execution requires separately qualified OS isolation.

The research-case assessment tool uses the pinned Codex runtime's explicit local sandbox profile. Failed calibration prevents measured-input execution. Assessment reports have no authority to advance a Run or accept a scientific result.

The local workbench uses loopback, exact browser origin and a session token. Project metadata and evidence APIs do not accept arbitrary shell commands or control roots. A missing Host permits new work in a new Host; old project copies remain read-only.

Scientific reports must distinguish synthetic and measured inputs, record methods and provenance, and require appropriate scientific review. A passing software or numerical benchmark is not physics acceptance. Do not silently replace raw data, accepted results or failed observations to obtain a pass.

Installed build metadata and owned workspace resolution do not broaden code-execution permissions. The private Host remains the filesystem access boundary; existing SQLite file modes are retained. ## Research SDK and local assets

Provider, malformed-model and refusal errors retain safe type/status diagnostics without copying private response bodies into derived error records. Attributable model outputs remain in the private research evidence stream; sanitizing an error does not erase that evidence.

PI/Postdoc/Reviewer tools are named Host functions, not generic filesystem or shell access. Model/tool effects are separately admitted; SDK retries, sessions, handoffs and nested agents are disabled. Literature requests use fixed INSPIRE/arXiv hosts without redirects and bounded responses. Search terms and requested paper IDs are sent to those services; private raw data and credentials must not be included in queries. Papers and stored notes remain untrusted evidence, never tool or approval instructions. HTML text reads do not establish figure inspection.

Local assets enter model context through named reads. Candidates remain provisional. A different-attempt agent reviewer can review with evidence actually read in that attempt; operator review remains optional and attributable. Method registration additionally executes the Host's independent finite C2/Normalization calibration on exact source bytes with a bound interpreter. Uploaded validation JSON cannot grant reviewed status, and unsupported contracts remain candidates. Reviewed code is atomically snapshotted read-only for the existing Code backend; it receives no direct execution permission. Passing finite calibration does not establish universal physical applicability.

Project captures verify registered producer scopes and copy only bound evidence. Raw-data backups, live SQLite, backend credentials and recovery authority are excluded. Current outcome/provenance labels require the actual terminal artifact and committed closure. Operator input and authorization provenance require actual attributed records; scientific adjudication remains system-originated; system closure never fabricates a Human Response or rewrites old acceptance records. CAS metadata edits cannot alter a Run's frozen project version. Model discussions cannot grant permissions or erase Host numerical warnings. System conclusions retain scope, limitations and unresolved claims.

## Shared autonomous task boundary

The existing Host coordinator owns the shared task quota; related Runs cannot reset it. Source policy currently permits four Runs, 128 actual model requests, 8,000,000 explicit input-plus-output reservation units and a 3,600-second dispatch deadline. Research generation/compact and every native SDK repeat are admitted before dispatch. Unknown usage keeps its maximum reservation. This is not a USD billing ceiling: provider-internal context, hosted-tool fees and the provider billing statement have distinct scopes.

Complete explicit input is limited to 256,000 tokens, with a common 194,560-token compaction setting. Research output is capped at 32,768 including reasoning; Code output is capped at 128,000. Limits live in one application settings module. The shared quota adds accounting without weakening original invocation, operation or cancellation fences.

A sealed PI experiment proposal can create a child Run using supported analysis parameters and reviewed methods. It retains exact dataset identity, interpreter and file/network permissions. Child slots are durably reserved before admission. Unsupported scope, absent new parameters and exhausted resources leave explicit unexecuted reasons. Original accepted results are immutable. The shared native driver resumes verified Code deliveries and reconciles completed parents; it does not replay uncertain external effects.

Optional operator scientific input binds Project version, exact content, optional Run/head and registered evidence references. The contribution API has no control writer. Text requesting approval remains scientific input and cannot grant authority. Contributions are incorporated at a subsequent safe research attempt; no active request or closed report is rewritten.

The CLI/background driver requires the original workspace's private application `.env`; credentials remain outside browser payloads and child environment inheritance. Status is read-only and does not launch work. Coordinator schema 3 rejects older Hosts rather than migrating them in place. Keep their original runtime/evidence; accepted history is never reclassified to satisfy the new workflow.

The native command proxy guard is essential to the extra-authorization boundary: a forged HTTP Origin/Host is not authentication against an unrestricted local shell client. Server origin/session checks remain unchanged. Regression probes use only owned synthetic HTTP/Unix services; coding commands cannot obtain their session sentinel through the proxy or direct bypass, and numeric commands have no network access. The native model/API transport remains separate. See the [official permission-profile documentation](https://learn.chatgpt.com/docs/permissions) for the proxy versus command-network distinction.
