# Verification

| Intent | Command |
| --- | --- |
| Static correctness/import checks | `ruff check src tests scripts setup.py` |
| Core protection | `python scripts/check.py` |
| Affected behavior | `python scripts/check.py tests/path.py::test_name` |
| Workbench presentation, citations and browser submission logic (Node 22.7+ for tests) | `node --test tests/workbench_*.mjs` |
| Integration | `python scripts/check.py --integration` |
| Numerical benchmark | `python -m lqcd_agent.benchmark` |
| Deployment preflight | `lqcd-agent doctor` |
| Local CLI timings | `python scripts/measure_cli.py --samples 3` |
| Portable evidence check | `lqcd-agent verify-archive --archive-path /absolute/archive.zip` |
| Research case input integrity | `python -m lqcd_agent.research_cases verify` |

Core has 12 critical checks. Integration runs the current scientific, command-policy, durability, storage and CLI tests once, then nine numerical benchmark cases. Test counts are not acceptance criteria. Old results are not reused as evidence for this version.

The measured C2/Normalization case assessments are separate from those nine lightweight numerical checks. `tests/test_scientific_codegen.py` also runs both families through normal scientific planning, CodeHost delivery, actual isolated execution, Host review and autonomous closure using synthetic deterministic backend fixtures. Separate mock-provider checks retain complete production-size summaries and Host diagnostics. Regressions cover changed data, effective-code/runtime drift, pending plans, empty coding contracts, nonzero calculation exits, dependency-free cancellation and idempotent delivery. These fixtures do not claim model or physics quality. Input packs, references, generated programs and reports remain local. `tests/test_research_cases.py` verifies source-preserving extraction, replica identities, independent numerical checks and actual sandbox read/write denial without measured data or API calls. Live programming and real-input assessment require the explicit operator actions in the [case guide](RESEARCH_CASES.md); ordinary CI does not spend API credits or depend on the external research project.

The Code-consumption regression uses actual sandbox syntax verification and advances the trusted clock by 35 seconds before publication, beyond the old controller default but within the original execution capability. Its companion advances beyond that capability deadline and verifies refusal, retained uncertain state, absent registered results and unchanged same-key replay. The controller reuses the existing CodeHost lease window; these checks do not raise backend, producer, dispatch or active-time limits.

`tests/test_durability.py` exercises invocation reads on fresh offline Host authority: first/hit deep-copy isolation, current raw/revision changes, strict-JSON and authorization rejection, stale-CAS refusal, and primed reads at exact lease-expiry and execution-deadline boundaries. These checks do not call a provider or reuse an expired live Host.

JSON regressions distinguish nested finite scientific floats from explicitly bounded control numbers and reject NaN, Infinity, exponent overflow, unsafe integers and duplicate keys. The synthetic C2 fixture retains an uncertainty of `1e20` through sealed code, actual Analysis, Reviewer findings and the final report without changing numerical quality rules. Fresh-Host regressions also reject oversized invocation/operation timestamps and producer deadlines/windows after same-revision raw-record changes; legitimate nullable and pre-dispatch states remain readable.

A passing check requires a nonempty selection, actual zero exit and JUnit without failures, errors or skips. Reports and raw JUnit go into a fresh root under the approved execution parent (`/private/tmp` on macOS). `check-results/latest.json` and `check-results/integration.json` point to the latest completed targeted/core check and full integration attempt; original failed reports retain their status. Affected checks and a full integration run have distinct scopes. Integration binds source, lock, build inputs and CI configuration before and after execution; ignored bytecode, package metadata and macOS `.DS_Store` files do not participate. Passed tests clean only their own fresh roots; failed roots are retained for diagnosis.

The runner also exports `check-results/ci-summary.json` and `ci-junit.xml`. The summary contains only selection/outcome, duration, source digest and benchmark status. Public JUnit contains case names, durations and outcome tags; it omits file paths, failure messages, captured output and private runtime references. CI uploads only these two files for seven days, including after a failed check. Detailed evidence and runtime directories remain excluded. Unit checks exercise privacy-preserving export and changes to build/CI inputs invalidating source identity.

For ordinary code edits, run the affected tests. Do not rerun the complete suite to update a document. For docs, check relative links and `git diff --check`. Tests are maintained according to behavior and risk, not a required case count.

`tests/test_prompt_context.py` checks lossless long instructions, Unicode and retained source isolation. `tests/test_context_window.py` checks that Postdoc and Reviewer counting/generation requests carry identical strict output schemas with all fields required, including nullable `next_experiment`. It also exercises the actual research SDK serializer with HTTP fixtures: complete input counting including tools/output schema, a forced final conclusion even after compaction, repeated compaction with the original scientific state intact, the 256,000-token ceiling, insufficient headroom, Host refusal, and cancellation/timeout cleanup for generation, counting, compact and tools. `tests/test_codex_context_gate.py` exercises the real loopback HTTP gateway with fixture upstreams: exact-limit admission, count failures and excess, forbidden implicit history/routes/transports, streaming, connection reuse, bounded identical-input count retries, slow-stream count deadlines, shutdown before response headers, connection cleanup and private trace contents. `tests/test_context_host.py` checks the real Host ledger for compact/generation call sharing and pre-model counting failures. `tests/test_research_preflight.py` checks request-construction failure artifacts against the real attempt record. These tests do not call paid models. `tests/test_science_integrity.py` checks that untrusted Reviewer fields cannot erase Host findings or invent acceptance evidence; `tests/test_workflow.py` verifies autonomous scientific closure without a Human Response. Supported/qualified/inconclusive outcomes retain actual decision provenance, and additional authorization remains separately scoped.

The checkout's Python 3.12 environment and `.venv` are ignored local dependencies. Standard console scripts and `python -m lqcd_agent` use the installed package. Follow the [single environment and lock-generation procedure](../README.md#develop); install with `--require-hashes` and set `TMPDIR` to the approved execution parent first (`/private/tmp` on macOS). Execution uses the fixed native macOS parent; no deployment-profile environment override is supported. Set `LQCD_AGENT_WORKSPACE` when the operator workspace differs from the current directory. Current environment qualification belongs in [Current state](REPO_CURRENT_STATE.md).

Deploy on qualified storage. Do not use a live SQLite file as a cross-node shared database, loosen locking or synchronization, or copy a live database as a backup. Use the coordinator's consistent backup operation.

Live qualification is explicit and separate from offline pytest. A live result applies only to its recorded source/build, model, input and executed workflow; earlier single-call provider results do not qualify the current research SDK collaboration. Retain failed attempts separately and distinguish successful model execution from scientific acceptance. Ordinary test runs do not read application credentials or start paid SDK jobs. Use the commands and boundaries in the [README](../README.md#application-api-and-coding) for an operator-authorized live check; detailed reports stay local and the current qualification summary belongs in Current state.

Native macOS checks exercise actual storage, boot/PID identity, process stop and child cleanup, cancellation and stable clock epochs across CLI processes. Unreadable or changed process identities must not authorize signalling. An extra-authority pause still requires the scoped explicit response; normal scientific closure needs none. A successful model review or synthetic oracle does not prove physical correctness.

`tests/test_delivery.py` builds a wheel with a deliberately stale source manifest, installs it in a fresh virtual environment and runs doctor plus a scientific case outside the source checkout. Locked third-party dependencies are reused offline; the application must come from the installed wheel. `tests/test_engineering_assembly.py` covers nested/ambiguous configuration, the registered record-input program, malformed CSV and failed-review propagation. `tests/test_inspection.py` verifies status neither constructs executors nor changes authority files; unknown schema is tested in memory. Actual SDK model/tool waits are observed without changing authority or making the Attempt runnable. Regressions reject unpublished or forged resource suffixes, foreign owners, unknown execution settlements and gaps between settled and newly reserved effects. A passive Codex metadata fixture checks the shared original job directory and rejects a redirected backend root, without model calls or backend construction. `tests/test_archive.py` covers closure admission, idempotence, unchanged sources, scientific member tampering and unsafe ZIP paths/types.

The GitHub workflow pins actions, grants read-only repository access, checks deterministic lock generation and installed dependencies, and runs Ruff plus offline integration on macOS. New pushes cancel older checks for the same workflow/ref. A separate Ubuntu job checks source/generated consistency, the numerical kernel and wheel construction using runner-owned temporary storage; it never opens an application authority or claims runtime qualification. Pure-contract tests run without site packages against an unavailable storage profile, and an architecture check prohibits control-to-graph imports. Local checks do not certify remote CI. The CLI timing probe reports independent-process samples, median and maximum; it retains measured Hosts and does not call paid APIs. Small samples measure local engineering overhead, not scientific capability or a production latency SLO.

Archive verification is content/inventory checking, not a replay, origin authentication without a separately trusted digest, or physics acceptance. Archives exclude SQLite and do not replace the coordinator backup API. Coordinator schema 3 rejects old Hosts. There is no in-place migration, accepted-result rewriting, automatic cleanup or unrestricted execution.

## Scientific evidence and context

`tests/test_research_evidence.py` verifies exact consumed-byte provenance, changed-data refusal before calculation, explicit missing-input identity, and inherited input identity during a real scientific Replay. It also checks that models select program IDs while the Host creates mappings, rejects forged identities/paths and duplicate/unknown selections, preserves pending proposals, and supports digest-checked context section reads. Existing workflow, durability, cancellation, archive and credential tests remain part of integration.

Read a role's evidence catalog from its `llm_calls/<role>.json` request message. In Python:

```python
from lqcd_agent.llm.context import read_context_evidence

# output_dir is the scientific role's recorded domain output directory.
# catalog is the evidence_catalog from that role's request JSON.
source = read_context_evidence(output_dir, catalog, 'repo_inventory', fields=['analysis_programs'])
```

Planner sources are `user_goal`, `case_config`, `repo_inventory` and `research_context`. Reviewer sources include the complete supplied `method_plan`, `run_result`, Host `review_evidence`, review scope and `research_context`. The scientific adapter supplies remediation and relevant Run history in `research_context`; collaboration additionally supplies structured project state. Standalone callers may omit that context. The initial Reviewer view contains a method-step count and named-read instruction; `test_scientific_codegen.py` checks that the complete method remains retrievable. A referenced digest identifies one immutable bundle; missing sections, changed bytes, symlinks and hardlinks are rejected. This helper reads local evidence and grants no execution, approval or control authority. Model messages contain selected views, not command logs or a general filesystem-reading tool. Archives include these bundles through the existing scientific member inventory.

Architecture regressions compare deterministic and optimistic-provider review of negative matrix errors, missing/malformed matrix data and failed/malformed run input. Provider failure must retain Host warnings. Real role requests must receive frozen remediation/history, and caller mutation must not alter retained context. CLI workflows check immutable ledger extension and reject mixed ordinary/verification owners and illegal intermediate budget or clock states even when all following record hashes, prefix bytes, indexes and intent digests are recomputed. Application credential tests verify that the research SDK receives the application key without exporting it to child environments; native Codex receives only the temporary loopback gateway credential.

`python scripts/measure_context.py` measures fixed offline request character sizes (messages and compact JSON Schema separately) and 50 invocations of the current eight-point numerical program. These are payload sizes and local computation timings, not tokenizer counts, API latency, cache hit rates or scientific quality estimates. Live provider qualification is separate and requires explicit authorization; see [Current state](REPO_CURRENT_STATE.md) for executed qualifications. Ordinary checks do not spend API credits.

## Project collaboration verification

`tests/test_research_intake.py` exercises the actual research SDK with offline model fixtures: declared-data profiling without raw-array disclosure, fixed operator inputs, explicit metadata supplementation, PI prerequisites retained until supported by actual evidence reads, supported configuration construction and honest offline behavior. `tests/test_intake_flow.py` runs preparation through a real Host into the existing Code/Analysis path with a deterministic backend, preserves the shared quota and original Project, and refuses changed data or an expired task. Workbench regressions cover empty Project starts, recorded questions, replies without dispatch, explicit same-budget continuation and duplicate-parent refusal. These checks do not establish paid model planning quality.

`tests/test_numerical_trials.py` verifies the development tool with real producer authority and actual numerical sandbox execution, including bounded feedback and exact sealed receipts, failure/unknown preservation, mixed-tool budget refusal and original process-group cleanup on success, timeout and cancellation. Its local fake upstream exercises the actual native SDK MCP transport: failed trial feedback, corrected input, successful trial, Code delivery, formal Analysis, Reviewer evidence and unattended closure. It does not call a paid API. Full native trial cancellation and deliberately detached descendants are not qualified by these tests. Synthetic development feedback is not independent calibration or private-data qualification. Final generated Analysis retains the same source/input/environment and scientific evidence checks.

The native Codex worker also has an offline real-SDK test using a local fake upstream: a transient 503 recovers in the same worker, each generation request is recounted, path-only output reads actual workspace bytes, and failed-response usage remains incomplete. It does not call paid models or establish scientific correctness.

The research SDK tests run the actual SDK Runner with deterministic SDK Model outputs or an in-memory HTTP transport. They do not establish live model quality. Tests cover per-effect admission/settlement, unknown usage, tool/model cancellation cleanup, bounded turns, no nested agents, independent reviewer input, issue persistence and attributable references. Planning retains unanswered scientific questions as implementation checks even if both roles repeat them as `blocked` while recommending execution. Explicit missing prerequisites still block and require a verified answer; omission, relabeling and invented evidence cannot release them. Review retains all unresolved blocked questions. Scientific revision tests exercise real control cycles and budget exhaustion, preserving warnings, autonomous conclusions and final report evidence. Authorization fixtures retain the original pause/head/scope checks.

Real HTTP-SDK/Host batch regressions request more tools than the original attempt can fund. Reviewer and PI must each finish with a real counted JSON response inside the unchanged model/tool budget; deferred calls have no execution resource or `tool_start`/`tool_end` evidence. Time-pressure coverage preserves closing resources, and a separate regression retains legitimate reads on the penultimate model turn. Count and generation must carry the same tool policy. Unaffordable compaction may retain complete history below the hard input limit, with an explicit pressure record.

Project/library tests cover empty installation, CAS edits, immutable versions, source/Host-executed validation binding, atomic reviewed method snapshots, conflicting dispositions, admission idempotency, producer-scoped captures and history after execution storage loss. Optional-contribution HTTP checks exercise operator attribution, Project/Run/head binding, original-key replay, registered evidence, unchanged control logs, digest chains and concurrent duplicate input. The replica-observable test executes an actual isolated synthetic program and checks Host arithmetic plus retained physics limitations. Method registration executes finite independent calibration and rejects an uploaded pass receipt as execution proof. Supported method families are C2 and Normalization; generic contracts remain candidates.

Research tool tests exercise correction of malformed candidate literature URLs before any asset writes. Direct library validation still rejects them; missing write authority, stale asset revisions and actual Host lease expiry still raise rather than returning a candidate. Unknown or mistyped current Run section IDs return only `not_registered` and exact catalog guidance; the same fixture then reads the exact registered ID and still rejects altered bytes, missing files, redirected paths and invalid page offsets. Fixed-energy C2 checks reject a null energy error and accept finite conditional `0.0`; external rest-energy uncertainty remains unpropagated.

Generated-analysis tests capture the actual Reviewer context after real Code/Analysis execution. The complete numerical member must match the original domain output bytes and hash, remain unchanged after an Agent mutates its context, and be readable across SDK tool pages without clipping large finite floats. Tampered member bytes still fail the original reader's integrity check.

The arXiv/INSPIRE tests use transport fixtures and retain source/hash/page behavior. External service availability, paper figure reading and paid live PI/Postdoc/Reviewer runs are separate qualifications and are not implied by offline passes. Failed/unregistered role traces remain in the original Host and are not claimed as captured project artifacts. `tests/test_context_state.py` checks large histories, unresolved issues, contradictory answers with original evidence, and conditional conclusions drawn only from accepted captures. Full history is retained for named reads; its initial projection has no fixed byte ceiling.

The [context policy](ARCHITECTURE.md#research-roles-and-sdk-boundaries) for the current Terra configuration admits at most 256,000 tokens per complete explicit input, with research compaction above 194,560. Native Code uses an effective 243,200-token window and 194,560-token compaction threshold, backed by actual HTTP input counting. Count failure prevents generation; oversized inputs are not silently truncated. Balanced research roles share eight model calls per attempt, including compaction, with the first role bounded to leave turns for the second. The final model allowance forbids further tool calls and requires a structured conclusion. Research generation allows up to 32,768 output tokens; Code has an explicit 128,000 output-token cap. An incomplete research response fails without retry or publication. The shared research-task quota separately limits four Runs, 128 actual generation/compact requests, 8,000,000 explicit input-plus-output reservation units and a 3,600-second dispatch deadline. Each native SDK repeat consumes quota and unknown usage stays conservatively reserved. These units are not a USD billing ceiling or a complete measure of provider-internal context and tool fees. Qualification must record the actual configured model and executed paths; fixture results do not establish live compaction quality or physics validity.

Shared-driver checks cover the same CLI/workbench launcher, native Host lock, original workspace, filtered child environment, incompatible/uncertain-work refusal and autonomous scientific completion. The driver reconciles supported sealed `next_experiment` proposals through canonical admission; tests must establish linked immutable Runs, same data/interpreter/permissions, shared quota across children, original-key crash reconciliation, and finite unexecuted reasons. Read-only status must not launch work or replenish resources. Ordinary checks use local fixtures without paid APIs; live capability is qualified only for its recorded final build.

`tests/test_sandbox_network.py` uses local fake model responses with the actual pinned native SDK: a requested `require_escalated` command is refused under native `never` before execution, the forbidden sentinel stays absent, and the worker can finish its permitted path-only response. The production-profile checks in `tests/test_openai_runtime.py` and numeric checks in `tests/test_research_cases.py` use owned HTTP/Unix sentinels to test proxy-aware and direct-bypass attempts without touching the operator's real workbench, credentials or paid APIs. Public-network availability is a separate deployment probe; these local regressions do not depend on an external website.
